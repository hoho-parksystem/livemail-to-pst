# 實機驗證清單

目前本機未安裝 Redemption，因此尚未完成真正的 EML → PST 匯入測試。本版本在完成以下檢查前應視為實驗性。

1. 準備匿名樣本：純文字、HTML、Big5／UTF-8、中文主旨／檔名、多收件者、寄件備份、草稿、multipart/alternative、CID 圖片、一般及大型附件、無 Date、異常 MIME、空檔。放入多層、中文、含空白及方括號的資料夾。
2. 安裝相符位元數的傳統版 Outlook、Windows PowerShell 5.1、Redemption，記錄版本；在隔離測試帳號上關閉 Outlook 執行轉換。
3. 確認來源檔案的雜湊與修改時間不變；來源數 = saved + failed。空檔預期失敗；異常 MIME 結果應個別記錄。
4. 開啟 PST，確認階層、封數、主旨、正文、寄件者、收件者、日期／時區、附件與 CID 圖片。附件另存後與來源已知附件比對 SHA-256。確認草稿等狀態，不可僅憑封數通過。
5. 執行期間切換 Outlook 視窗、開啟無關郵件，確認不會誤匯入其他郵件。確認沒有寄信或讀取回條。
6. 模擬單封失敗、中斷、磁碟不足、記錄無法寫入。確認失敗不計成功、記錄缺 summary 的情況可辨識，部分 PST 保留供檢查；既有 PST 不可重跑覆寫。
7. 重跑同一輸出應拒絕；改用新 PST 應可重新完整匯入。同時執行兩個程序指向同一輸出，第二個應拒絕。
8. 結束後確認 PST 可正常開啟及備份，原 Outlook profile 沒有新增永久資料存放區；分別驗證 32／64 位元。

在 Issue／PR 附上匿名環境版本與逐項結果；若某項未驗證請明列。測試資料不得包含真實使用者郵件。
